# 1) ساختار کامل برای دسکتاپ

## 1.1. اصول کلی Layout دسکتاپ
- **Desktop-first**
- حداقل عرض پیشنهادی: `1280px+`
- استفاده از **Sidebar ثابت** در بخش مدیریت
- در بخش عملیاتی اپراتور:
  - **Top Bar ثابت**
  - **Grid کارت‌ها** برای سفارش‌ها
  - **مودال‌های بزرگ / full-screen centered**
- همه فلوها باید بدون رفتن به صفحه جدید، تا حد ممکن در مودال‌ها انجام شوند.

# 2) ساختار کامل برای موبایل

> در موبایل همان المان‌ها را نگه می‌داریم،  
> اما به‌جای 2 یا 3 ستون، همه‌چیز **تک‌ستونه، پله‌ای، و bottom-sheet friendly** می‌شود.

---

## 2.1. اصول کلی Layout موبایل
- عرض پایه: `360px–430px`
- همه صفحات **single-column**
- در صورت نیاز:
  - Tabs افقی
  - Collapse section
  - Bottom sheet / Full-screen modal
- دکمه‌های اصلی همیشه:
  - بزرگ
  - تمام‌عرض
  - نزدیک انگشت

---

## 2.2. Login در موبایل
### چیدمان
- لوگو بالا
- عنوان
- کارت ورود تمام‌عرض
- فیلدها زیر هم

### المان‌ها
- موبایل / نام کاربری
- رمز عبور
- نقش (اختیاری)
- ورود
- فراموشی رمز

### نکات
- کیبورد مناسب فیلدها
- دکمه ورود sticky نباشد مگر لازم باشد

---

## 2.3. داشبورد اپراتور در موبایل
### چیدمان
```
┌───────────────────┐
│ Top Bar           │
├───────────────────┤
│ Search            │
│ Filters (scroll)  │
│ ثبت خودروی جدید   │
│ Car Cards list    │
└───────────────────┘
```

### تفاوت با دسکتاپ
- **Top Bar فشرده**
- Search و Filterها زیر هم یا به صورت horizontal scroll chips
- Grid کارت‌ها:
  - یک ستونه
  - در گوشی‌های بزرگ شاید دو ستونه
- کارت‌ها full width

### المان‌ها همان‌اند
- دکمه ثبت خودروی جدید
- فیلتر وضعیت
- جستجو
- پروفایل

---

### چیدمان: full-screen step-by-step
در موبایل بهتر است به‌جای 2 ستون، به‌صورت مرحله‌ای نمایش داده شود:

#### ترتیب پیشنهادی:
1. دوربین و ثبت تصویر
2. نتیجه AI
3. فرم تکمیلی
4. ثبت ورود

### ساختار
- Header ثابت:
  - عنوان
  - دکمه بستن
- بدنه:
  - Live camera
  - دکمه ثبت تصویر
  - نتیجه AI
  - فیلدهای فرم
- Footer:
  - انصراف
  - ثبت ورود

### نکات UX
- بهتر است دکمه capture بزرگ باشد
- preview دوربین تمام عرض
- فیلدها زیر هم
- ویرایش AI واضح و ساده

---

## 2.5. کارت خودرو در موبایل
### ساختار کارت
- پلاک درشت
- badge وضعیت
- مدل + رنگ
- راننده + تلفن
- نیرو
- زمان ورود
- دکمه جزئیات / مدیریت

### تفاوت با دسکتاپ
- اطلاعات بیشتر به‌صورت collapse یا line-wrap
- دکمه‌ها full width یا stacked
- call button برای تلفن راننده

---

## 2.6. مودال مدیریت کارت در موبایل
### چیدمان پیشنهادی: Tab یا Accordion
در موبایل، 3 ستون دسکتاپ باید به 3 سکشن تبدیل شوند:

#### تب‌ها:
1. خدمات
2. نیرو
3. سامری

یا

#### آکاردئون:
- خدمات
- انتخاب نیرو
- خلاصه

### ترتیب نمایش
- اول اطلاعات خودرو
- بعد خدمات
- بعد نیرو
- بعد خلاصه
- سپس دکمه تحویل

### چرا؟
چون در موبایل فضای افقی محدود است و باید تصمیم‌گیری مرحله‌ای شود.

## 2.7. بخش خدمات در موبایل
- سرچ خدمات

  - تحویل به نیرو

# 3) تفاوت چیدمان دسکتاپ و موبایل به‌صورت خلاصه

| بخش | دسکتاپ | موبایل |
|---|---|---|
| Login | کارت وسط صفحه، عرض محدود | کارت تمام عرض، فشرده |
| داشبورد اپراتور | Top bar + grid چندستونه | top bar فشرده + لیست تک‌ستونه |
| ثبت خودرو | 2 ستون | full-screen step-by-step |
| مدیریت کارت | 3 ستون | تب/آکاردئون |
| پرداخت | 3 ستون | عمودی / تب‌دار |
| گزارشات | sidebar + جدول | drawer + کارت / جدول اسکرولی |
| تنظیمات | تب‌ها + فرم‌های بزرگ | تب/آکاردئون + فرم‌های تک‌ستونه |

# 4) پیشنهاد نهایی ساختار سیستم طراحی

اگر بخواهی این پروژه تمیز و قابل توسعه بماند، پیشنهاد می‌کنم:
- **همه صفحات در یک design system واحد**
- **همه مودال‌ها با هدر ثابت + فوتر اکشن ثابت**
- **همه کارت‌ها با ساختار یکسان**
- **همه status badgeها با رنگ ثابت**
- **همه summaryها با یک الگوی واحد**

# 5) نسخه بسیار کوتاهِ معماری UI

## دسکتاپ
- `Header`
- `Sidebar` یا `Top filters`
- `Main grid/content`
- `Right summary panel` در مودال‌ها
- `Full-screen modal`

## موبایل
- `Top bar`
- `Search + filter chips`
- `List / cards`
- `Full-screen modal`
- `Bottom sticky actions`
- `Tabs / accordion`

---

اگر بخواهی، در پیام بعدی می‌توانم این را به یکی از این 3 شکل تبدیل کنم:

1. **وایرفریم متنی دقیق برای هر صفحه**
2. **ساختار کامپوننتی React / Next.js**
3. **نقشه صفحه به صفحه با اندازه‌ها و spacing دقیق**
